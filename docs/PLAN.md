### 2.0 実装レーンの選び方 ★③に入る前に必ず決める

**先に「どちらのレーンで書くか」を決める。** これを決めずに parser へ手を伸ばすのが「1効果1時間」の主因だった。

| レーン | 使う条件 | 書く先 | 検証 | 目安 |
|---|---|---|---|---|
| **速い（既定）** | **同型が2枚以下** | **`manualEffects.ts` に手書き** | `build:effects` → **逆翻訳を目視** → `golden -- --only` ＋ `smoke`（計 約5秒） | **1件 5〜10分** |
| **遅い（例外）** | **同型が3枚以上** ／ 新しいアクション型・条件型を足す ／ `src/engine/` を触る ／ `src/screens/` を触る | `effectParser.ts` ほか | 現行フル（§2.1 ③〜⑤） | 1件 30分〜数時間 |

- **根拠（次に読む人はここを消さないこと）**＝`npm run census:clusters` の実測で **1テンプレあたり 1.14効果**（2026-08-29）→ 再測 **1.03**（2026-08-30・母数が 571→340 に減っても比は改善しない）。⇒ **parser に regex を1本足しても平均1効果しか直らない。** ⚠**在庫が戻れば（新カードで同型が増えれば）遅いレーンへ戻す。**
- 🔴**「移設だけ」の manual 化は禁止**＝parser の出力を中身そのままコピーしても ①**何も直らない** ②`vocabCensus.ts` が STUB/MANUAL を高シグナルから免除するので**間違いが計器から消える** ③収穫マージが MANUAL/PARTIAL を効果単位で不可侵にするので**以後の parser 改善が永久に届かない**。**書くのは「原文を読み直して正しい JSON を手で書く」こと。** ⚠トップレベル効果の `parseStatus` は `MANUAL`／`PARTIAL` のみ（`manual-fields` ゲートが強制）。
- **母集団は「§5.3 の索引」そのものから取る**（旧版の3計器＝census 高シグナル／`census:cards --sheet 1`／意味照合台帳 は 2026-09-01 に**同時に底を打った**＝母集団としては使えない）。**索引を上から取り、着手前にその項目の母集団だけを実測する。**
- 🔴**在庫の総量を測る手段は、いま無い**（「原文にフレーズがあるのに live にキーが無い」型の計器は受け皿の別名を全部知らないかぎり必ず過大に出る＝9回連続で外した）。⇒ **「あと何割か」に答えようとせず、残項目数だけを報告する。**

### 2.2 完了の定義 ★実機検証の要否はここで決まる（旧 §2.3 を統合）

**「⑤実機まで毎回」はやらない。触ったディレクトリで機械的に決める。**

| 触ったもの | 完了に要るもの |
|---|---|
| **`src/screens/` を触った**（UI・支払い・提示ゲート・モーダル・タイミング） | 🔴**⑤実機まで。** golden で反転確認を取っていても**省かない** |
| **新しいアクション型・条件型・機構を足した** | 🔴**⑤実機まで**（型は足したが engine のどこも消費していない、を実機で炙る） |
| **`src/data/` `src/engine/` `public/data/` だけ** | **④まで**（`gates` 緑＋ live の A/B 差分）。実機は不要＝`V-nn` の登録も要らない |

- **golden/smoke/fuzz が守れない層が実在する**＝`persist.commit` と React 反映のタイミング差／UI の選択リセット／モーダルの候補絞り込み。**この層の唯一の防御が実機シナリオ**（回帰トリップワイヤとして残す）。実例＝`O-123` は `artsUseGate.ts` の1行が壊れており、**JSON にも逆翻訳にも現れず3計器がどれも動かなかった**。
- **`src/screens/` を触ったのに省略してよい唯一の条件**＝**実機から原理的に観測できない**とき（例＝`optional`「〜してもよい」の【自】は CPU が自動応答して画面に出ない）。このときは **golden で両方向を固定し、理由を §5.1 に `V-<次番号>` で登録**する。**「時間がないから次回」は該当しない。**
- **④まで（実機不要と判定した回）は、それが「完了」**＝「要実機検証」と書いて次セッションへ送らない（判定した理由を BUGFIXES に1行書く）。
- 1巡のスコープは**⑤まで1セッションで回せる大きさ**に切る＝**速いレーン10件／バッチ**、**遅いレーン15〜20効果／バッチ**が目安。

## 3. 不変の運用ルール

- **`effects_*.json` の curated 値は上書きされない**＝`build:effects` は ①`parseStatus` が `MANUAL`/`PARTIAL` を含むカードを**カード単位で温存**（`PRESERVE_STATUSES`）②それ以外も fresh が curated の純粋な上位集合でなければ**温存して held へ送る**（`buildEffectsJson.ts:158-162`）。**変わるのは `heldReview --adopt` で明示採用したものだけ。**
- **逆翻訳を直したらエンジン実装までセット**（乖離＝偽陰性を作らない）。語彙が無ければ §5.3 の機構として実装するか、`engineUnwiredTimings` に登録し逆翻訳へ `【※engine未配線】` を付けて明示する。[[decompile-engine-parity]]
- **ゲートは `npm run typecheck`（＝`tsc -b --noEmit`）**＝plain `tsc --noEmit` は project references を見ず CI が拾うエラーを見逃す。⚠`scripts/` は型チェックの対象外＝**`scripts/` を直したら実際に `npm run golden` を走らせるまで「直った」と言わない。**
