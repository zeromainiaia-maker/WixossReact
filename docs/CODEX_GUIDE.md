### ⚠️ 落とし穴（すべて実測で踏んだもの）

| 症状 | 原因と対処 |
|---|---|
| `patch rejected: writing is blocked by read-only sandbox` | **`-s workspace-write` / `--full-auto` が config の `sandbox_mode` を上書きした**。Windows では workspace-write が実質 read-only。⇒ **サンドボックスフラグを一切付けない** |
| `orchestrator_helper_exit_nonzero: ... -1073741502` | `-s workspace-write` を付けた／Windows `0xC0000142`。後者は**実装とゲートは完了しているのに最終報告だけ書けない**形で止まる（続き400〜402 で3回連続）⇒ **検証側が引き取る前提でスコープを切る** |
| `exit 2` | `codex exec` は **`--ask-for-approval` を受け付けない**（TUI 用） |
| Claude 側の分類器にハードブロックされる | コマンドラインに **"danger" 文字列**を出した（`-c sandbox_mode="danger-full-access"` / `--dangerously-bypass-*`）。⇒ **書かない**。無害な `-c` は通る |
| 起動コマンドが分類器に回る | **`Bash(codex *)` は前方一致**＝`cd ... && VAR=... && codex ...` の複合コマンドや `$(cat ...)` を含めると一致に失敗する。⇒ **`codex` で始まる単体コマンドにし、指示書は `-` + stdin で渡す** |
| 10分でタスク通知が `killed` で来る | **殺されるのはラッパーだけで `codex.exe` は生き残って完走する**（ログが 2.8MB→135MB まで伸び `-o` も後から出た実績）。⇒ `tasklist \| grep codex.exe` で生存確認し、生きていれば `until [ -f <-o> ] \|\| ! tasklist \| grep -qi codex.exe; do sleep 20; done` で待つ。⚠**その間に Claude 側で `build:effects` 等を走らせると競合する** |
| kill 後に held が増えて見える | **`_held_fresh.json` が stale**（採用直後に再生成される前で止まる）。⇒ **必ず `build:effects`→`heldReview` を再実行してから読む** |
| `net::ERR_NETWORK_ACCESS_DENIED` | **サンドボックスはファイル書込を許可するだけでネットワークは別軸**＝Supabase / 実ブラウザを要する検証は Codex 側では実行できない。⇒ **シナリオコードだけ書かせ、実行検証は Claude 側でやる** |
| 着手前に exit 0 で停止（実装ゼロ） | 投入時に**ワーキングツリーが汚れていた**＝Codex が「ユーザーの既存変更を許可なく破棄しない」と判断した（判断自体は正しい）。⇒ **投入前に `git status --porcelain` を空にする**（計器を回したら `git checkout -- <生成物>`） |

**進捗の見方**：`git status --porcelain` と `git diff --stat`。ログは巨大（1〜10MB）なので**全部読まない**＝`grep -n "tokens used" <log>` で最終レポート位置を出してから Read で該当箇所だけ読む（`awk`/`tail` パイプは分類器に弾かれやすい）。

### ⚠️ 検証のベースラインは commit SHA で確定する

**検証を始める前に `git log --oneline -3` でベースラインを確定し、`git show <baseline>:path` で比較する。**
`HEAD` を使うと自分のコミットと比較して**差分ゼロに見える**。

> 🔴 **2026-08-26 続き675 実測＝自動コミットフックは復活している。** codex の完走とほぼ同時に
> `auto: docs/BUGFIXES.md, docs/_census_stubs.txt, … (+13)` というコミットが**16ファイルを勝手に確定した**
> （`e6490075c`・codex 終了の1分後）。**未検証の作業がコミット済みで着地する**ので、
> **検証は必ず `git show <投入前の baseline SHA>:path` と比較する**（`HEAD` は自分のコミットになっている）。
> ⚠**「作業ツリーが汚れているか」で codex の変更を追ってはいけない**＝フックが先に掃除してしまい `git status` は空に見える。
> ⚠ 確定したコミットのメッセージは `auto:` の機械生成なので、**検証後に `git commit --amend -F <file>` で書き直す**
> （未 push なら安全）。
> 📌 履歴＝2026-08-24 時点では `.claude/settings.local.json` に `hooks` キーが無く「存在しない」と記録していた。
> 元々は `PostToolUse` が Write/Edit のたびに `git add -A` + commit し、**scratchpad への書き込みでも発火して**
> codex の未検証作業が勝手にコミットされた（続き210 の `061f423b`）。**この節は消さずに実測で更新すること。**
> ⚠**フックの有無にかかわらず、codex の実行中に Claude 側でリポジトリを触ったら「どれが codex の変更か」が混ざる**＝
> **触るなら先にコミットしてベースラインを確定してから触る。**

### 読み取れる傾向

**信用してよいところ**
- **数値（ゲート・件数・diff 集合）は正確。** ただし独立実行はする。
- **明示的に要求した項目は守る。** 要求していない副作用は報告しない＝**必要な報告は全部書き出す。**
- **保守的な採用は褒めると継続する**（続き209 で約40件を見送った判断は正しかった、と指示書に明記した）。
- **自分の過去の判断を訂正できる。** ただし**促さないとやらない**（→§5-7）。
- **時間切れ時は機構単位で完結させ「未完了」を正直申告する。** 続行指示（実装済み分＋残作業＋優先順位）で2回目に完走＝**大きいバッチは2段投入を前提に設計してよい。**

**外すところ**
- **同型の配線が複数箇所に必要なとき、1箇所で満足する。** 「複数箇所ある」と書くだけでは足りず、**§5-15 のとおり経路の関数名を報告させて面を可視化する。**
- **既存の同義実装を触らず並行新設する**（`fieldDown` の横に `signiDown`／`BASELINE_HIGH` の横に `CENSUS_BASELINE_HIGH`）。巨大な既存 regex を「壊すのが怖い」方向に倒れる。⇒ **Claude が実測時に同義の既存語彙を特定して「これを拡張せよ／並行新設禁止」と名指しする**（一般論では防げなかった）。
- **明細を書かなかったカードの原文照合が甘い**（明細を書いたカードは正確に直す）。⇒ スコープ全カードに「現行の誤り」明細を付けるか、付けられないカードには「1効果ずつ原文照合」を個別に念押しする。
- **指示書に書いた「目標形の概形」は、誤っていてもそのまま実装される**（ただし報告6項目で自主申告はされる）。⇒ **概形を書くなら根拠まで書く**（「原文に『まで』が無いので `pickUpTo` は false」）**か、値を空欄にして「原文から決めよ」と明示する。**
- **「触るな」と書いた部分に改善の余地があっても、守って据置する。** ⇒ **次バッチのスコープへ明示的に繰り入れる**と回収できる。**「触るな」は永久放置の指示ではない**と Claude 側が覚えておく。

**🔴 Claude 側が外すところ（通算12回・5バッチに1〜2回の頻度で覆される）**
- 🆕**自分で書いた worklist の登録票も「標本」**（続き644＝`O-57` の登録票「実測4効果」は、母集団を切り直すと **169効果中の真の穴7**だった）。**登録票は「次に着手する人へのメモ」であって母数ではない**＝§3-1 の「簿記を信用しない」は**自分が数日前に書いた行にも効く。**
- **最も高くつくのは「engine は実装済み」型の先回り。** 続き629＝`totalLevelMax` を「parser 専業」と書いたが**読むのは `execBanish` だけ**で、指示書どおりなら**死フラグ4件（JSON だけ直って挙動不変）**だった。⇒ **「実装済み」と書くならその効果が通る exec の該当行を読んでから書く。読めていないなら「実装済みか確認せよ」と書く**ほうが安全。
- 覆される原因はほぼ3つ＝①**JSON を `slice(0,N)` で切って読み後続 leaf を見落とす**（§5-3-3⁸）②**行番号がどの関数の中か確かめない**（§5-2′）③**母集団をカード単位の個数差で数え、兄弟効果に相殺される**（§5-3-3⁹）。
- **「機構待ち」の在庫は投入前に消費側コードで確かめると過半が parser 専業に落ちる**（続き443＝裸STUB 7枚のうち4枚は engine 実装済みだった）。
- ⇒ **Codex は鵜呑みにせず実コードを読むので、訂正されたら素直に受け入れて指示書の前提を直す。** §7 の「Codex が『一致』と書いた逆翻訳を自分でも照合する」は、**『不一致』と書いた項目こそ優先して読む**と読み替えるほうが実効的だった。
