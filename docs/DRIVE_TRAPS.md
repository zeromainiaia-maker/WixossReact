### 4.4 実機シナリオの罠（着手前に必読）

> 🔴**この節が要る理由**＝ソフトロックのバグは **smoke / fuzz / golden / CPU がすべて「クランプする側」の経路しか通らない**ため、**全ゲート緑のまま人間だけが操作不能**だった。同様に `O-123` は `artsUseGate.ts` の1行が壊れていて **JSON にも逆翻訳にも1バイトも現れず、3つの計器がどれも動かなかった**。⇒ **`src/screens/` に関わる疑いは、実機を書くまで「直った」と言わない。**
> 🔑**engine の真バグも実機からしか出ないことがある**＝「このターン手札から捨てた」台帳の書き漏れ（10箇所が3種類に割れていた）／`ON_ATTACK_SIGNI` の遅延トリガー二重積み／`TRANSFER_TO_DECK.position` の `second`/`third` が実経路に無い、はすべて実機由来。🔑**真因は3件とも「同じ式を2箇所以上に書いた」こと**＝片方だけ機能を足すと**JSON も型も golden も緑のまま、実際に使われる経路にだけ実装が無い**。🔑**二重発動は肯定側テストでは緑になる＝回数まで assert する。**

1. 🔴**`spec.hostSet`／`guestSet` の両方に `'field.check': null` を必ず入れる**＝`injectScenario` の `CORE_FIELD_KEYS` に `check` が含まれ**リセットされない**。前シナリオのライフクラッシュ確認モーダルが全画面を覆い**クリックが1つも通らない**（3回踏んだ）。⚠🆕**2026-08-24（続き637）＝引き継がれるのは `check` だけではない。`CORE_FIELD_KEYS`（`lrig` `signi` `assist_lrig_*` `check` `key_piece*` `free_zone` `beat_zone`）は全部そう**で、**使うシナリオが自分で書き切らない限り前シナリオの盤面が残る**。実例＝`guardExtraColorlessSufficient` が `field.signi` を固定しておらず、直前シナリオが置いた `WX18-039`（【常】レベル２と３でガード不可）が残って**手札の Lv2 サーバントが「正しく」候補から消え**、engine バグに見える FAIL になった。**盤面依存の判定をするシナリオは `field.*` を自分で固定する**。⚠**後始末も自分でする**＝ライフクラッシュを起こして抜けるシナリオは `field.check` を消化（「エナに送る」まで）してから返す。
   ＋🔴**盤面 spec は「CORE フィールド」を明示クリアする**（2026-09-01 続き769 実測）＝`field.key_piece` / `key_piece_extra` /
   `hand` / `deck` / `energy` などは `injectScenario` の**除外方式が消さない**ので、**前の巡の1枚が残ったまま**次のシナリオが回る。
   症状は「**【召喚】ボタンが出ない**」のような**別の場所の空振り**になるので、カード・ルリグ限定・待ち時間を疑って時間を溶かす。
   ⇒ **「盤面に1枚あるかどうか」で結果が変わる観測をするときは、その枠を両サイド明示的に null / [] にする。**
   ＋🔴🆕**`life_cloth` は注入しない**（`O-248`）＝作った instance id を積むと**注入そのものが通らなくなり**、
   全シナリオが別ゲームを掴むようになった（入れた直後に4本中3本が落ちて発覚）。
   ＋🔴🆕**盤面 spec の「CORE フィールド」に `field.check` と `life_cloth` も入れる**（`O-238`）＝
   前の巡の `field.check` が残ると「ライフクロスクラッシュ」モーダルが**全操作をブロック**し、
   症状は「押したいボタンが出ない」という**別の場所の空振り**になる（2回誤読した）。
2. 🔴**`getByRole('button', { name: <正規表現>, exact: true })` は `count()` が常に 0**（`exact` は文字列名にしか効かない）＝**モーダルもボタンも出ているのに30反復空振り**する。ラベル照合は `data-action-label` の前方一致か `H.clickBtn`/`clickTextOrBtn`/`clickTestId`。
2c. 🆕🔴**「同じ index を押し続けるとトグルで選択が外れる」＝2026-08-29 に1セッションで3回踏んだ**（スペルのエナ選択・複数 pick・`O-135`）。
   複数枚を選ばせる UI（`spellcost-energy-N` / `pick-N` / `optcost-energy-N`）は**押すたびにトグル**なので、
   `.first()` や固定 index を毎ティック押すと**選んで外してを繰り返して永久に揃わない**（実測＝26ティック空振り）。
   ⇒ **押した index を `Set` で覚えて、未選択のものだけを1つずつ押す。** 揃ってから確定ボタンを押す。
   ⚠`H.stdStep` は**「決定 (1/」しか見ない**＝2枚以上選ばせる画面では pick を1枚も押さずに素通りするので、自前で積む。
   ＋🔑**候補モーダルは「このモーダルで選んだ札」を覚える**＝毎ティック同じ札を押すと選択がトグルして `決定` に永久に進まない（続き769 で2回踏んだ）。
   ＋🔑🆕**ゾーンの行動一覧（`my-signi-zone-N`）はトグル**＝毎ティック押すと開閉を繰り返し、**開いた瞬間を1度も観測できない**。
   ⚠**「ボタンが0本」で開閉を判定してもいけない**（盤面には常時「ルリグアタックへ／エナに送る／終了」が出ている）＝
   **アタック系のラベルが見えているか**で判定する。
2d. 🆕🔴**ゾーン選択ボタンを `.first()` で取らない**（2026-08-29・`V-89`）＝マッチする最初のボタンが
   **disabled**（自分が居るゾーン／ライズ条件不一致）だと、そこで打ち止めになって `SELECT_SIGNI_ZONE` のまま空振りする。
   ⇒ **全マッチを `nth(i)` で走査して、visible かつ enabled な最初の1つを押す。**
2b. 🆕🔴**`H.clickTextOrBtn` を CHOOSE のボタンラベルに使わない**（2026-08-24・`O-55`）＝**盤面ログのテキスト**（「ハトハットを【トラップ】として設置しますか？」）に当たって**「押せた」と報告しながら何も進まず 34反復まるごと空振り**する。ボタン限定の `H.clickBtn` を使い、**先に進む側（2段目のゾーン選択など）から**試す。⚠罠2（`exact` が効かない）と合わせて、**ラベル照合は「ボタン要素に限定」＋「前方一致」**が既定。
3. 🔑**負方向テスト（「出ない」「起きない」）は必ず対照とセット**＝**単独では何も検証していなくても緑になる**。対照は**盤面を1文字も変えず原因だけを外す**（実例＝`damageSource` の1語／guest ルリグ1枚／相手資源の枚数）。
   ＋🔑**回数制・置換の対照は「同じ札・同じ操作で1ビットだけ反転」して測る**（別カードで反転すると別経路を踏んで比較にならない）。⚠**patch のあとを固定 sleep で済ませない**＝`queryState` で反映を観測してから次へ進む。
   ＋🔴🆕**「出ないこと」を主張する実機には、必ず「出る側」の対照を隣に置く**（`O-238`・2026-09-05）＝
   `o238GrantGatedByOtherSigni`（他にシグニがいるので引用【自】が**提示されない**）は単独では**付与機構ごと壊れていても緑**で、
   反転確認（`activeCondition` を削る）で**一度 PASS した＝判別力ゼロだった**。`o238GrantAloneNormalAttack`（単騎＝提示される）を
   足して初めて反転が赤になった。**negative 側を書いたら positive 側も同じ巡で書く。**
3b. 🔴🆕**反転確認の判定は「旧挙動で観測できる痕跡」から書く**（2026-08-26 続き674・`O-73`）＝
   新実装を前提にした witness を必須条件にすると、**旧形へ戻した反転確認が「前提崩れ」で落ちて
   旧挙動の再現が判定文から読めない**。実例＝`o73DelayedMillTrigger` は「設置を観測した時点の `powerMods`」で
   即時実行を判定していたが、**旧実装には「設置」自体が存在しない**ので値が永久に null になり、本題の判定に
   到達しなかった（反転確認を2回走らせる羽目になった）。⇒ **「設置を1度も観測しないまま相手のパワーが下がった」**の
   ように、**旧実装でも必ず残る痕跡**を本題判定の先頭に置く。⚠これは 📌3 の「対照とセット」とは別軸＝
   **対照の作り方ではなく、FAIL 文言が原因を指すかどうか**の話。
4. 🔑**「盤面だけを見る判定」も偽陽性**＝**機構を1度も通らなくても同じ盤面になる**ことがある（続き466 の実例＝対話が出なくても身代わり成立と同じ絵）。**機構が動いた証拠（問いログ・`asks` 件数など）を必須条件に入れる**。
5. 🔑**クリック前から成立している条件で判定しない**＝`pendingEffect==null && stackLen===0` は**効果の開始前と完了後の両方で true**。**効果が走り出したことを1度でも観測してから判定する**（さもないと単体で PASS・バッチで FAIL の位置依存 flakiness になる）。
6. 🔑**候補が複数ある選択で `pick-0` を盲目に押さない**。⚠🔴**ただし `pendingCandidates` の index を `pick-<idx>` にそのまま使うのも誤り**（続き469 で判明）＝**相手の場が対象のときモーダルは候補を reverse して描画する**（`EffectInteractionModal.tsx:189-192`＝`targetScope==='opp_field'` なら `[...candidates].reverse()`）。`data-testid` は**表示順の index**（`:282`）。⇒ **集合として assert してから `[data-testid^="pick-"][data-card-num="<カード番号>"]` で狙う**（`clickPendingInstance`）。⚠**`data-card-num` はカード番号でインスタンスIDではない**＝**同名カードが複数並ぶ盤面では一意にならない**ので、そのときは表示順を自分で反転して index を出す。⚠先例 `cheatingSameLevelDownFilter` が index で動いていたのは**有効候補が1件しかなかったから**。
7. 🔑**DOM の描画待ちを必ず入れる**（続き469 で2回踏んだ）＝`H.queryState()` は **Supabase を直接照会するので DOM より先に真になる**。`pendingCandidates` が立った瞬間に `pick-*` や `決定 (N/M)` を掴みにいくと**0件で即 null**。**待機予算は 3秒程度で全ヘルパに揃える**（`clickPendingInstance`／`clickExactVisibleText`）。⚠**500ms だと1回目 PASS・2回目 FAIL の位置依存フレークになる**。
