### 4.3 計器の読み方

#### 🆕🔴 第3の系統＝「engine は正しいのに逆翻訳だけが嘘をつく」（2026-09-09・5件を系統化）

**engine の穴（＝JSON どおりに動かない）／golden の腐り（＝古い期待値）と並ぶ3本目**。
**逆翻訳は原文照合の主計器**なので、ここが嘘をつくと**照合そのものが機能しなくなる**（＝バグを見ても気付けない）。
実測5件はすべて **payload を engine が消費しているのに `decompileEffects.ts` が描いていない**形だった:

| 症状（逆翻訳の出力） | 実際の engine 挙動 | 直した軸 |
|---|---|---|
| `REMOVE_ABILITIES{target:LRIG, alsoCenterLrig}` が「センタールリグと**すべてのシグニ**」 | 候補はセンタールリグ1枚だけ | 対象が `LRIG` なら「センタールリグは」 |
| `TAKE_FROM_UNDER_SIGNI{count:'ALL'}` が「**ALL枚**まで」 | 好きな枚数 | 内部トークンを日本語へ |
| `TRASH{HAND_CARD,opponent}` ＋ `targetsStored` が「（**相手が選ぶ**）」 | 先に対象宣言した1枚に固定 | `targetsStored` を先に見る |
| `ADD_TO_FIELD{targetsTriggerSource}` が「トラッシュのシグニ1枚」＝自由選択 | `triggeringCardNum` の1枚 | 「そのカード（トリガー元）」 |
| `hasGuard:false` が**丸ごと消える** | `matchesFilter` が効かせている | `false`（否定）も描く |
| 🆕`leaveUnderCardsTrash.minUnderCards` が**丸ごと消える**（「下にカードが3枚以上ある」が出ない） | engine は3枚未満で fail-closed している | 成立要件の枚数も描く。⚠**`count` が数値のときは書かない**＝「カードN枚をトラッシュに置く」が同じ数を既に言っており `minUnderCards === count` は導出値 |
| 🆕`BANISH_SUBSTITUTE{powerReduction}` が「**がバニッシュされる場合**」＝原文より**狭い** | 消費地点は**離場 funnel の `powerReduction` 軸1本だけ**でバニッシュ経路には意図的に足していない（`effectEngine.ts:7192` に「ここへ足すな」と明記） | payload の形で分岐して「が対戦相手の効果によって場を離れる場合」へ。engine が実際にやっている「他の」（victim 自身の除外）と「ターン終了時まで」も描く |

⇒ **payload にキーを1つ足したら、`npm run regen` 後の `docs/decompile_sheet*.txt` に

🔑**「挙動を壊さない嘘」は engine のバグと同じ重さで扱う**＝次に着手する人の**母集団の切り方を狂わせる**

🆕🔴🔑**2026-09-13（第303／第304・`O-348`）＝この系統を直す作業そのものが、同じ系統を新しく生む。**
payload キー22種を `decompileEffects.ts` に配線した回で、**4件が「新しい分岐を足したせいで、
その関数が既に描いていた語が黙って消える」**形だった（**全部ゲート緑のまま通った**）:

| 足した軸 | 消えた語 | なぜ気付けなかったか |
|---|---|---|

②**早期 return を書いたら、同じ関数の他の分岐が描いている軸を全部列挙して持ち込む**
③**条件つきの新分岐は、条件を外れたときの落ち先を読む**（落ち先が「今回直した嘘」なら、その分岐は無条件にする）

＝**計器が緑になったことは「正しく描けた」の証拠ではない。`git diff docs/decompile_sheet*.txt` を原文と3列で読む。**

🆕🔴**最悪形＝逆翻訳が「原文を regex で抜き出して」描いている**（2026-09-09 第243・`COPY_TARGET_POWER`）。

**JSON の期限が欠落していても逆翻訳は原文どおりに見えていた**＝**計器がバグの共犯**になっていた

- 🆕🔴**「N セッション連続で同じ FAIL が再現する」は「本物のバグ」の証拠ではない**（2026-08-29・`V-89`）。

  「`git stash` しても HEAD で FAIL＝本セッション起因ではない」と正しく確認されて次へ送られていた。
  **真相は「シナリオが assert している UI が live にもう存在しない」＋「spec の deck に候補カードが1枚も無い」**で、
  **あの数字こそ仕様どおりの挙動だった**。⇒ **FAIL を寝かせる前に、まず「live JSON を読み直して、
  シナリオが assert している形が今も出るか」を確かめる**（§4.1「実測そのものが嘘をつく」の実機版）。
  ⚠**「HEAD でも再現する」は「engine のバグである」を意味しない**＝計器が古いときも同じ見え方をする。
- ⚠**golden は「修正前データで実際に落ちるか」を確かめてから採る**＝フィルタ無しでも候補の先頭がたまたま正解で **vacuous に PASS** することがある。**対象を候補の先頭以外へ置く。**
- ⚠**枝の数を固定した golden トリップワイヤは、正しい是正でも落ちる**＝`join(',')` の完全一致ではなく「全エントリが opponent かつ1つ以上」のような性質で書く。


- 🔴🆕**census の較正キーは「免罪符」になる**（`O-132`・第181バッチ／旧 PLAN §5.3 から移設）＝
  キーを表に足して黙らせると、**そのキーが JSON から消えても census は静かに合格し続ける**。
  実例＝「それぞれ１枚まで」は `PLAY_FREE` 2本で表され、`execPlayFree` が最後に `SEARCH{maxPick:1}`
  （0枚選択で確定できる）を出す＝**`PLAY_FREE` それ自体が「1枚まで」の上限スロット**なので上限キーは構造上いらない。
  ⇒ **キー表には足さず**、`extraOk` の残渣チェック（need ≤ slots）に slot として1つ数えて払い戻した
  （足すと「同じ効果の別アクションにある『N体まで』の脱落」まで隠れる）。
  🔑**較正したら必ず golden に「較正の根拠キーが live に実在する」を追加する**＝
  根拠が消えても計器が黙らないようにする（反転確認＝根拠キーを壊すと golden が FAIL）。

### 4.5 修正を live へ届ける経路（届かないと恒久 no-op になる）

- 🔴**`build:effects` の収穫マージは `parseStatus:MANUAL`／`PARTIAL` の効果を不可侵にする**＝`manualEffects.ts` を後から直しても **live には永久に届かない**（新しい id の追加だけは通る）。届けるには **`npx tsx scripts/syncManualLive.ts <CardNum>`**。⚠実行後は必ず `npm run gates`（live を直接書くので、ゲートだけが安全網）。
- 🔴**parser を直したのに live が変わらないときは、まず3ファイルを見る**＝`docs/_held_fresh.json`／`_partial_fresh.json`／`_idset_fresh.json`。**id 集合が live と fresh でズレたカードは `_idset_fresh` に出る**（実測46カード）。
- 🆕🔴**`parseStatus:MANUAL` なのに `manualEffects.ts` に実体が無いカードがある**（2026-08-24・`O-54`＝`WXDi-P08-038`）＝過去の外科パッチが刻印だけ残した **live 限りの遺物**。この状態だと **`syncManualLive` は「同期元が無い」ので効かず**、`build:effects` はカード単位 PRESERVE で永久に凍る。**直し方＝`grep <CardNum> src/data/manualEffects.ts` が空なら、live の `parseStatus` を `AUTO` へ戻してから `build:effects`→`heldReview --adopt`**（以後 parser 改善が届くようになる）。⚠戻す前に **fresh が live の全情報を保っているか**を effectId のリーフパス単位で必ず確認する（本件は fresh が上位＝BURST の `isUp` 脱落まで同時に直った）。
- ⚠**`manualEffects.ts` のトップレベル効果は `MANUAL` か `PARTIAL` のみ**（`AUTO` と書くと `manual-fields` ゲートが exit 1）＝`mergeManualEffects` は `parseStatus` を見ず effectId 一致で常に manual 側を勝たせるので、`AUTO` の手書きコピーは **parser の最新出力を永久に上書きし続ける**。
- ⚠**`build:effects` は破壊的ではない**（curated は温存され、`heldReview --adopt` で明示採用したものだけが変わる）。正しい規律は「実行禁止」ではなく**「実行後に effectId 単位で全数比較して、意図した件数だけが変わったことを確認する」**（出力は minified 1行なのでテキスト diff は役に立たない）。
- ⚠**カード単位 PRESERVE で held に載らない効果**（同居効果が MANUAL 等）は `build` では直せない＝`effectId` をアンカーにした**外科パッチ**で JSON を直接訂正する。共有関数にカード固有テーブルを埋めるのは禁止。

- 🆕🔴**held の原因は「消えた／変わった／増えたリーフ」を機械で出してから読む**（2026-09-06・`O-262`）＝
  `WX20-053` は**変わったリーフが `parseStatus` の1つだけ**（AUTO→PARTIAL）で、それが `isPureSuperset` の
  唯一の不一致になり **`trashActivated:true` を持つ fresh を採用できず held に居座っていた**。
  🔴**その PARTIAL は偽だった**＝`markSilentFallback` は**捨てられたパース試行からも刻まれる**ので、
  **最終 JSON に痕跡が1つも無いのに刻印だけ残る**（本件は `SEARCH.afterSearch` へ既に畳まれた文）。
  ⇒ 🔑**「採用は凍結と引き換え」なら、採用ではなく刻印の原因を消す道を先に探す**
  （`heldReview --adopt` で採ると live が PARTIAL/MANUAL になり、以後 parser 改善が永久に届かない）。
- 🆕**live が全 AUTO のカードは「配列まるごと」`isPureSuperset` に掛かる**＝`manualEffects.ts` へ手書きしても
  **1リーフでも既存値を変えると held に落ちて live に届かない**。⇒ **`npx tsx scripts/syncManualLive.ts --effect <CardNum>:<EffectId>`**
  で**その効果だけ**を届ける（カード単位で書くと、同じカードの他の効果で live のほうが新しい分を巻き戻す）。


- 🔴🆕**手書き shadow の `effectId` が live とズレるとカードごと凍る**（`O-93`・第179バッチ／旧 PLAN §5.3 から移設）＝
  `manualEffects.ts` 側が **`-E1b` / `-E2b` の枝番**で、**live の効果番号が原文の文の並びから1つズレて**いたため、
  カードが `_idset_fresh` に落ちて**そのカードへの parser 改善が何ひとつ届かなくなっていた**（実測21効果）。
  🔑**その凍結が実バグを6件隠していた**（「４つから２つ選ぶ」が1つしか選べない／相手のライフを増やす／
  keyword が UI と一致せず恒久 no-op ほか）＝**凍結は「変わらない」ではなく「壊れたまま固定される」。**
  ⚠**計器自身も嘘をつきうる**＝`censusManualDrift` は `buildEffectsJson` が**マージ後に重ねる印字キーワードコスト**を
  再現しておらず、乖離57効果のうち **36効果（63%）が偽陽性**だった。**乖離を読む前に計器の再現忠実度を疑う。**

- 🆕🔴🔑**parser を壊して `build:effects` しても live は戻らない＝反転確認で live が汚れる**
  （2026-09-12・§5.3 `O-335` で実測）＝収穫マージは **`isPureSuperset`（既存リーフを1つも失わない かつ 増える）**
  のときだけ採用するので、**リーフを減らす方向の変更は絶対に live へ伝わらない**。
  ⇒ parser を1行変えて「赤くなるか」を見る反転確認をやると、**赤くするために足した誤った値が live に焼き付き、
